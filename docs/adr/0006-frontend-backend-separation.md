# 前后端分离:前端独立构建与部署(取代 go:embed 内嵌)

## 状态

已接受(取代 ADR-0001 的"单二进制部署"在后台 UI 上的延伸,以及 ADR-0003 的 go:embed 影响项)

## 背景

早期方案把前端构建产物通过 `go:embed` 内嵌进 Go 二进制,以"单二进制部署、运维成本最低"为由(ADR-0001)。该方案在纯 Go 部署下成立,但在本项目的实际部署形态下收益不成立,而代价持续累积:

1. **开发反馈被阻断**。改一行前端样式必须 `pnpm build` → `go build` → 重启后端,才能看到效果。前端本可以 `pnpm dev` 秒级热更新,却被迫走完整打包链路。
2. **构建产物入库**。Vite 产物带内容 hash,45 个文件每次前端改动全部换名,为满足 `go:embed` 编译期可读,`web/dist` 被迫纳入版本控制,与 `.gitignore` 中 `web/dist/` 的规则直接矛盾。
3. **构建镜像无法重建前端**。`docker/Dockerfile` 只有 golang 基础镜像,不含 node,只能 `COPY . .` 使用入库的产物。CI 无法从源码构建出可发布镜像。
4. **发版节奏被绑定**。前端与后端无法独立发版,任何一侧改动都要重建并重新部署整个后端二进制。
5. **单二进制收益已不成立**。生产形态早已是 `docker compose` 多容器(postgres + backend + caddy),入口反代由 Caddy 承担。"少一个静态文件服务器"并不减少实际运维对象。

## 决策

彻底拆分前后端,不再内嵌:

- `docker/Dockerfile` 提供两个独立构建目标:
  - `backend` —— 纯 Go 服务,镜像内无任何前端文件
  - `web` —— nginx + 前端构建产物,镜像内无任何后端代码
- 生产编排新增 `web` 服务,Caddy 负责 TLS 与按路径分流:
  - `/api`、`/internal`、`/healthz` → `backend:8080`
  - 其余请求 → `web:80`(nginx 负责 history 路由回退与静态资源强缓存)
- 删除 `web/embed.go` 与 `internal/httpapi` 中的 `spaMiddleware`,后端不再承担任何静态资源服务职责。
- `web/dist` 从版本控制移除,`.gitignore` 规则恢复生效;前端产物只在镜像构建期生成。
- 开发环境:Caddy 按同构规则分流,`/api` 等转发到宿主机 Go 后端,其余转发到 Vite dev server(5173),改前端即时热更新,不经过任何打包。

## 影响

- **正面**:前后端真正分离,开发热更新即时生效;两个镜像独立构建、独立发版;`web/dist` 不再入库,仓库干净;CI 可从纯源码构建出可发布镜像。
- **代价**:部署单元从 1 个二进制变为 `backend` + `web` 两个容器,compose 需同时构建两者。`Caddyfile.prod` 需人工替换平台域名占位符(该限制原本已存在)。
- **未变**:租户子域(`*.<平台域名>`)的短链跳转与落地页仍整站由 Go 后端承载 —— 那是核心业务逻辑,不由 nginx 处理。
- **平台域名分流**:裸平台域名与 `app.<平台域名>` 行为一致,均提供后台 SPA;两者在 Caddy 中复用同一 snippet。
