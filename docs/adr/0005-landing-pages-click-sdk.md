# 落地页型短链:外部/上传页面 + 导航式点击端点 + 每短链生成 SDK

短链新增第二种类型:落地页型 (landing)。访问时先重定向到落地页(租户自建的外部静态页,或租户上传、由平台托管的 zip 压缩包页面),落地页按钮经平台 JS SDK 绑定点击回传,点击计入该短链的点击次数(与访问数并列的裸计数器)并最终到达目标 URL。

## 背景与权衡

**落地页不内置**:考虑过由 CLOAK 渲染内置落地页模板 + 落地页管理后台。否决:那是一套 CMS(模板、字段、样式管理),而租户实际需求是 自己的静态页面;外部页面 + 上传托管两种来源已覆盖,且与现有 同域按短码命中 路由模型完全兼容。

**点击回传 = 一次导航,而非 beacon 上报**:考虑过 SDK 先 fetch/sendBeacon 上报计数、前端再自行跳转目标。否决:两段动作存在竞态与广告拦截风险、目标 URL 必须暴露给页面、计数与跳转可能脱节。最终点击是导航到 GET /{code}/click:一次请求完成 计数 + 302 到目标,无 CORS,目标 URL 只存库,不用 SDK 直接写 a 标签也能用,计数与跳转天然一致。

**SDK 身份 = 脚本 URL,而非 referer 或短码属性**:短码只在域名范围内唯一,外部页面只拿短码无法确定归属哪条短链。SDK 由 GET /{code}/sdk.js 生成(服务器按 Host+code 解析短链,内嵌点击端点绝对地址):上传型页面相对引用即用,外部页面用绝对 URL 跨域引用也不依赖 referer(隐私模式/直开/预取会丢 referer)。

**落地页跳转固定 302**:301 会把 短码→落地页 缓存进浏览器,租户修改 landingUrl 长期不生效;重定向方式(301/302)配置仅对跳转型直达目标生效。

**点击为裸计数器**:访问 (Visit) 已记录 UA/IP/来源/时间明细;点击与访问并列,只计数不记明细(计数器列为 links.clicks,原子 +1)。

## 后果

- /{code}/click 与 /{code}/sdk.js 是公开 URL 契约,租户页面一旦引用即难以更改(新增路径只增不改)。
- 上传落地页占用磁盘(uploads/{linkId}/),逻辑删除保留、彻底删除/切换来源清理;单包 10MB、500 文件上限可配。
- 点击计数与访问数同一信任模型(导航即计数,无去重/防刷),爬虫直接请求点击端点会虚增点击数——v1 接受。
- 上传页面在租户自己域名下运行任意 HTML/JS(与开放重定向同一信任边界);平台默认域名按租户子域隔离,不触碰后台会话域。
