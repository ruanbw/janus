# 访问明细带动作与成功失败;落地页点击明文化

访问记录此前只有一种含义:"这次成功跳走了"(IP、User-Agent、来源页、时间)。租户问"这条短链为什么最近没量""这些流量是从哪来的""点了按钮的人是谁",系统答不了:停用、逻辑删除、目标为空、落地页文件缺失这些失败一律 404 且不留痕;落地页按钮的点击更是只落在 `links.clicks` 这个裸计数器上,没有任何明细。这次把"动作 + 成功失败 + 失败原因 + 最终目标"显式落到 `visits` 行上,并让点击也在同一张表落一行。

## 背景与权衡

**明细用一列动作枚举,而非按类型拆表**:考虑过为落地页视图、点击各建一张表,或给 visits 加 `is_click` 布尔。否决:三者的列结构完全相同(IP/UA/来源/时间/动作结果),拆表会让"这个短链最近发生了什么"变成多表 union;布尔列则无法再扩展动作。加一列 `action` 取 `redirect` / `landing_view` / `click`,配合 `outcome` 与 `reason`,一行就能自解释。

**点击明文化,而非新建 clicks 明细表**:`links.clicks` 继续作为计数器(列表页 O(1) 展示),但每次点击同时在 `visits` 落一行 `action='click'`。否决"只留计数":点击的 IP/UA/来源与访问同样是租户要看的证据,有了行就能按同一套筛选/分页/保留期策略复用,不必为点击重写一套统计管道。代价是 visits 行数约为原 2 倍,但明细本就按保留期滚动清理(90 天)。

**访问次数口径 = 成功的跳转/落地页视图**:点击行与失败行都不计入 `link.visits`。点击计入会把"到达率"算高一倍;失败计入会让停用中的短链显示"访问量在涨但一个都没跳走"。两个聚合入口(`CountVisitsByLink` 与 `fillLinksMeta`)必须同步过滤,否则单条链接与列表页会给出不同数字。

**只记录可归属到具体短链的失败**:短码压根不存在(404 未命中)、域名未激活、租户被封禁这三种失败无法归属到任何短链,不记——记了也无法在访问列表页呈现,且会给未命中的 404 流量发一条 INSERT。为此把"命中判定"拆成两套:`ResolveLink` 维持严格口径(未删除 + 启用)供落地页子路由使用;新增 `LookupLinkForVisit` 放宽为"短码命中即可用",并返回 reason(`link_deleted` / `link_disabled`)供调用方落失败明细。两套查询共用同一段 SQL(`lookupLink`),避免两份条件漂移。

**统计写入永远不阻断跳转**:明细写入失败只吞掉错误,跳转照常。短链服务的第一职责是把人送到目标 URL,不能因为统计表抖动而变成 500。

**地理字段先占位不接数据**:当前无 GeoIP/ASN 数据源,`country` / `is_datacenter` / `asn` 先建列为空值,前端按"空即显示占位符"渲染。接 mmdb 后只需在 Go 侧解析填充,不改表结构、不改前端。同样地,`lang` 取 `Accept-Language` 的首个语言标签并做长度上限保护,避免客户端可控的超长头把明细行撑大。

**落地页 upload 来源文件缺失改为 404**:此前访问裸短码会 302 到 `/{code}/`,再由静态路由 404,等于多一跳且什么都不留。改为在跳转处理器里直接判定 `landing_missing`:返回 404 并落一行失败明细,租户能立刻看出"落地页文件被删了"。

## 后果

- `visits` 新增 8 列(动作/结果/原因/目标/国家/数据中心/ASN/语言),迁移会为历史行回填动作:落地页型短链的旧访问归为落地页视图,其余保持跳转。
- 点击计数的时序变了:`IncrementClicks` 移到选到目标之后,没有可用目标的失败点击不再计数(此前失败也 +1)。
- 逻辑删除后的短链仍会产生明细行(失败)。这是"记录可归属失败"的既定代价;物理删除仍连带清理明细。
- 未命中的 404 依然不记任何行,"短码不存在"造成的流量损失仍无法统计。
- `GET /api/links/{id}/visits` 新增 `action` 过滤参数,非法取值返回 400(不静默返回全量)。
