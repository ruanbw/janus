# CLOAK 短链服务 — 规格

## Problem Statement

我想搭建一个自托管的短链服务:买域名、把 DNS 解析到自己的服务器,然后在后台添加域名,系统自动为它申请免费的 HTTPS 证书并在到期前自动续期;每个短链可以关联多个域名。这是一个多租户系统,任何人都可以注册使用,但目前没有任何代码,需要从零实现。

## Solution

一个部署在单台服务器上的**多租户短链服务**(CLOAK):
- 租户注册后,管理自己的**域名**与**短链**;添加域名后系统自动完成 **DNS 激活校验 → HTTPS 证书签发 → 自动续期** 的全流程;
- 每条短链由**短码 + 目标 URL + 一组关联域名**构成,同一短码可在不同域名下指向不同目标;
- 提供**后台管理界面**(Vben Admin)与 **RESTful API**,前后端分离;
- 平台部署者拥有**平台管理员**角色,可治理全平台(查看/封禁租户、调整等级、移除违规域名)。

## User Stories

### 注册与认证
1. 作为访客,我想要用邮箱注册账号,以便成为租户使用服务。
2. 作为访客,我想要注册后收到验证邮件并点击验证,以便激活账号(防止垃圾注册)。
3. 作为租户,我想要用邮箱和密码登录,以便管理自己的域名和短链。
4. 作为租户,我想要在忘记密码时通过邮箱重置密码,以便恢复访问。
5. 作为租户,我想要登录会话默认保持 30 天(可勾选"记住我"),以便不用频繁登录。
6. 作为租户,我想要退出登录,以便在公共设备上保护账号。
7. 作为租户,我想要修改密码,以便保证账号安全。

### 域名管理
8. 作为租户,我想要在后台添加一个域名,以便用它承载我的短链。
9. 作为租户,我想要添加域名后系统自动校验其 DNS 是否指向本服务器,以便确认域名归属。
10. 作为租户,我想要看到域名的状态(待激活/已激活/校验失败/已停用),以便知道下一步该做什么。
11. 作为租户,我想要系统在 DNS 未生效时自动重试校验(最长 72 小时),以便我不用手动反复检查。
12. 作为租户,我想要域名激活后系统自动为其签发 HTTPS 证书,以便访问者看到安全链接。
13. 作为租户,我想要系统在证书到期前自动续期,以便证书永不过期。
14. 作为租户,我想要在后台看到证书签发状态(待签发/已签发/失败),以便排查问题。
15. 作为租户,我想要停用一个域名,以便临时下线该域名下的所有短链。
16. 作为租户,我想要删除一个域名(删除前须清空其上的短链关联),以便不再使用它。
17. 作为租户,我想要确认一个域名只能归属于一个账号,以便域名归属清晰。
18. 作为租户,我想要添加子域作为独立域名,以便为不同业务使用不同子域。
19. 作为租户,我想要手动触发一次域名重新校验,以便 DNS 变更后立即生效。

### 短链管理
20. 作为租户,我想要创建短链(填写目标 URL、选择关联域名),以便生成我要的短链接。
21. 作为租户,我想要自定义短码或留空自动生成,以便得到想要的短链接。
22. 作为租户,我想要把一条短链关联到我的多个域名,以便同一短链多域名可用。
23. 作为租户,我想要在不同域名下用同一短码指向不同目标,以便按域名区分投放。
24. 作为租户,我想要系统保证"同一域名下短码不重复",以便不会产生冲突。
25. 作为租户,我想要查看短链列表(短码、目标、关联域名、状态、访问数),以便管理。
26. 作为租户,我想要编辑短链的目标 URL、关联域名与跳转方式,以便修正。
27. 作为租户,我想要启用/停用短链,以便临时下线某条短链。
28. 作为租户,我想要删除短链(逻辑删除,记录与访问数据保留),以便不再提供该短码。
29. 作为租户,我想要彻底删除短链(连同访问数据),以便清理。
30. 作为租户,我想要设置自动生成短码的长度,以便控制短码风格。

### 跳转行为
31. 作为访问者,我想要访问"域名/短码"时被重定向到目标 URL,以便到达目的地。
32. 作为访问者,我想要系统默认用临时跳转(302),以便运营者随时修改目标。
33. 作为租户,我想要为特定短链配置永久跳转(301),以便利用浏览器/CDN 缓存。
34. 作为访问者,我想要访问不存在的短码时看到 404,以便知道该链接无效。
35. 作为访问者,我想要访问已停用或已删除短链的短码时看到 404,以便知道链接已下线。
36. 作为租户,我想要访问者能在任意我关联的域名下访问短链,以便多渠道投放。

### 配额与等级
37. 作为平台管理员,我想要租户拥有等级,以便按等级限制短链与域名数量。
38. 作为租户,我想要在达到短链/域名上限时看到明确提示(含当前用量与上限),以便知道需要清理或升级。
39. 作为平台管理员,我想要调整租户的等级,以便授予更多配额。
40. 作为平台管理员,我想要查看每个租户的配额使用情况,以便管理。

### 平台管理
41. 作为平台管理员,我想要查看所有租户及其数据,以便掌握平台状况。
42. 作为平台管理员,我想要封禁/解封租户,以便治理滥用。
43. 作为平台管理员,我想要移除违规域名,以便治理滥用。
44. 作为部署者,我想要通过环境变量指定超管账号,以便安全地完成初始化。

### API
45. 作为租户,我想要在后台生成/吊销 API Key,以便程序化调用服务。
46. 作为租户,我想要通过 REST API 创建、查询、删除短链,以便集成到自己的系统。
47. 作为租户,我想要 API 数据严格按我的身份隔离,以便安全。

### 统计
48. 作为租户,我想要看到每条短链的访问次数,以便了解效果。
49. 作为租户,我想要系统记录每次访问的 User-Agent 与来源页,以便后续做设备/终端统计。
50. 作为租户,我想要查看某条短链的访问列表(时间、UA、来源),以便核对明细。
51. 作为访客,我想要在注册时自选一个前缀,以便获得我的平台默认域名(如 mybrand.domain.com)。
52. 作为租户,我想要邮箱验证通过后自动获得一个已激活的平台默认域名,以便立即开始使用。
53. 作为租户,我想要用平台默认域名承载正式短链(与自有域名同等对待),以便快速上线。
54. 作为租户,我想要平台默认域名不计入域名配额,以便不影响我的配额规划。
55. 作为租户,我想要不能删除平台默认域名(只能停用),以便平台域名体系稳定。
56. 作为部署者,我想要在 DNS 上配置泛域名解析(*.<平台域名> → 本服务器),以便所有租户子域自动生效。

## Implementation Decisions

1. **架构(前后端分离,API-first)**:Go 后端提供 RESTful JSON API;管理端为 Vben Admin(Vue 3 SPA),消费该 API;Caddy 前置负责 TLS 终止与证书生命周期;Postgres 存储;Docker Compose 编排。前端构建产物经 go:embed 内嵌进 Go 二进制,维持单二进制部署;Caddy 将后台域名与租户域名统一反向代理到 Go,Go 按路由区分(后台/API 与跳转)。
2. **RESTful 约定**:资源导向、JSON、动词语义(POST 创建/PATCH 更新/DELETE 删除/GET 查询);统一错误响应结构;列表分页;错误码可机器判读。
3. **认证与会话**:邮箱 + 密码;密码用 bcrypt/argon2 哈希;登录签发 HTTP-only、Secure、SameSite 会话 cookie,配合 CSRF 防护(SPA 同源);会话默认 30 天(可勾选 remember-me)。注册需邮箱验证,邮件经 SMTP 发送——SMTP 凭据后续由部署者提供,mailer 做成可插拔,开发期用控制台/虚拟 mailer;提供密码重置邮件。
4. **超管初始化**:环境变量指定超管邮箱(如 `CLOAK_SUPERADMIN_EMAIL`);该租户记录带 `is_super_admin` 标志;首次登录引导设置密码;不用"首个注册账号即超管"。
5. **数据模型(schema)**:
   - `tenants(id, email, password_hash, tier_id, status[pending|active|banned], verified_at, slug 全局唯一, is_super_admin, code_length(默认6), created_at)`
   - `tiers(id, name, max_links, max_domains)` — 种子数据:免费档(短链 100 / 域名 10)
   - `domains(id, tenant_id, fqdn 全局唯一, origin[self|platform], status[pending|active|failed|stopped], cert_status[pending|issued|failed], dns_checked_at, cert_probed_at, activated_at, created_at)` — 物理删除(平台默认域名除外,不可删)
   - `links(id, tenant_id, code, target_url, redirect_status[302|301], status[enabled|disabled], deleted_at 逻辑删除, created_at)`
   - `link_domains(link_id, domain_id, code)` — **唯一约束 (domain_id, code)**,在关联层强制"同一域名下短码不重复"
   - `visits(id, link_id, domain_id, user_agent, referer, created_at)` — 保留 90 天,定期清理
   - `api_keys(id, tenant_id, name, key_hash, revoked_at, created_at)` — 明文仅生成时展示一次,库中存哈希
6. **域名生命周期**:自有域名添加 → `pending` → 立即 DNS 校验(A/AAAA 记录包含本服务器公网 IP)→ 失败进入重试队列(每 5 分钟、最长 72h)→ 成功置 `active` → 触发证书预签发探活(内部请求 `https://<fqdn>/`,on-demand 授权端点放行)→ 更新 `cert_status`。删除前须清空该域名上"未删除"的短链关联;停用后该域名下所有短码立即未命中。平台默认域名(origin=platform)创建即 `active`(泛域名解析已指向本机),不进入 DNS 校验;租户邮箱未验证或已封禁时,授权端点不放行其默认域名。
7. **跳转路由**:访问 `域名/短码` → 按 Host 定位 `active` 域名 → 短码经 `link_domains` 命中 → 记录 Visit 并更新计数(异步/批量)→ 返回 302/301(`Location` = 目标 URL);未命中/域名停用/短链停用或逻辑删除 → 404。
8. **Caddy on-demand 授权端点**:内部端点 `GET /internal/caddy/authorize?domain=<fqdn>`;仅内网可达。放行条件:该域名 `active`,且(自有域名)或(平台默认域名:前缀属于已邮箱验证、未封禁的租户);平台后台域名(裸平台域名)始终放行。否则拒绝签发——防止任意域名解析到本机即触发签发。
9. **配额强制**:创建短链按"未物理删除"计数对比 `tier.max_links`;添加**自有域名**按未删除计数对比 `tier.max_domains`(平台默认域名不计配额);超限返回 4xx 并附当前用量/上限。
10. **API Key 与公开 API**:管理端生成/吊销 API Key;公开端点用 Bearer/X-API-Key 鉴权;MVP 端点:`POST /v1/links`、`GET /v1/links`、`GET /v1/links/{id}`、`DELETE /v1/links/{id}`。
11. **管理端 API 面**(会话鉴权,供 Vben Admin):auth(注册/登录/登出/me/改密/忘记密码/重置)、domains(增删改查 + 手动重新校验)、links(增删改查 + 停用/启用 + 彻底删除)、visits(访问列表与计数)、api-keys、tenant(设置与配额用量)、superadmin(租户列表/封禁/调等级)。
12. **安全与防滥用**:注册/登录限流;目标 URL 存储任意协议文本(开放重定向),实现必须拒绝控制字符(CRLF)防 header 注入;授权端点限内网;Caddy 配置 max_certs 保护;所有管理端请求鉴权并按登录租户过滤数据。
13. **租户注册与默认域名流程**:注册时提交 `{email, password, slug}`;系统校验 slug 唯一(且不与任何既有域名 FQDN 冲突)后创建租户(`pending`)并同步创建 `origin=platform` 的默认域名记录(`{slug}.{平台域名}`,`active`、`cert_status=pending`);邮箱验证通过后置租户 `verified`,触发该默认域名的证书预签发探活,该子域即可承载短链。泛域名解析(`*.<平台域名>`)由部署者在 DNS 上配置。
14. **环境配置与开发/生产对齐**:代码只写一套,环境差异全部由配置承载:`CLOAK_PLATFORM_DOMAIN`(平台域名)、`CLOAK_SERVER_PUBLIC_IP`(DNS 校验比对地址)、SMTP(未配置时落到控制台假 mailer)、Caddy 证书签发器(生产 Let's Encrypt / 开发本地 CA)。开发环境通过 hosts 文件(SwitchHosts)把平台域名与租户子域指向 `127.0.0.1`,`CLOAK_SERVER_PUBLIC_IP=127.0.0.1`,Go 解析器默认读取 `/etc/hosts`,使 DNS 激活校验在开发环境走真实代码路径通过——无需"跳过校验"的分叉逻辑。

## Testing Decisions

- **单一 seam**:Go 后端 HTTP API 边界。测试驱动"运行中的 Go 服务 + 真实 Postgres"的黑盒 HTTP 请求,不 mock 内部函数、不断言内部结构。
- **只测外部行为**:例如——登录成功后能访问受保护端点、错误密码被拒;域名经"假 DNS 校验器/假时钟"从 `pending` 走到 `active` 再走到证书 `issued`;短链创建后 `域名/短码` 返回对应 302/301;重复短码(同域名)返回冲突;未命中/停用返回 404;配额超限返回 4xx;租户 A 的 API Key 访问不到租户 B 的数据;访问后计数 +1。
- **被测模块**:API 层(认证、域名、短链、统计、超管、API Key)与领域规则(配额、短码唯一性、生命周期状态机、租户隔离)。
- **Prior art**:greenfield,无既有测试;首批测试确立模式(表驱动 + httptest 真实服务 + 测试库),后续模块照此扩展。
- **开发环境即主要集成测试场所**:API 黑盒测试运行在开发环境配置的服务上;上线前须在开发环境走通全流程(注册 → 邮箱验证 → 默认域名激活 → 证书签发 → 创建/关联短链 → 访问跳转 → 统计),再切生产。

## Out of Scope

- 计费/支付/自助升级(等级由平台管理员调整)
- 完整统计可视化(移动端/PC/设备分布)——本次仅记录 UA 与来源,可视化二期
- 证书到期时间与续签进度展示(二期,需读 Caddy 存储)
- 自定义 404 页面(二期,按域名级)
- SMTP 实际凭据配置(部署者后续提供;mailer 可插拔)
- 国际化、主题定制、多语言
- 域名托管商集成(自动建 DNS 记录)——本方案要求部署者自行完成 DNS 指向
- 除 A/AAAA 指向本机外的其他归属校验方式
- 短链批量导入/导出
- 访问者 IP 记录与地域统计

## Further Notes

- DNS 校验需配置本服务器公网 IP(环境变量)。
- 短码字符集:`a-zA-Z0-9` 去掉易混淆字符(`0/O/1/l/I`),默认长度 6,租户级可配。
- 访问记录默认保留 90 天、可配置,后台定时清理。
- 域名删除时,其上"已逻辑删除"的短链一并物理清除;配额按未物理删除计数。
- Caddy 固定镜像版本,证书目录用持久化卷;启动时预签发送首个访问者零等待。
- 部署要求:DNS 上须配置平台域名的泛解析 `*.<平台域名>` 指向本服务器(以及裸平台域名本身,承载后台)。平台默认域名按子域逐个签发,受 Let's Encrypt 每注册域名每周 50 张证书(含续期)限制,该额度按平台域名聚合;规模接近上限时迁移到泛域名证书方案。
- 开发环境:平台域名 `cloak.test`(RFC 保留测试域)。用 SwitchHosts 把 `app.cloak.test` 与每个测试租户子域 `{slug}.cloak.test` 指向 `127.0.0.1`(hosts 文件不支持通配符,租户子域需逐条加,SwitchHosts 多组即可);Caddy 用本地 CA(`tls internal`)为测试域名签发本地证书,执行一次 `caddy trust` 让本机浏览器信任根证书。Caddy 本地 CA 与 on-demand 的组合指令在实现期先用小 spike 验证。
